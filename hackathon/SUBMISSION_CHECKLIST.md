# Final Submission Checklist

The attached hackathon brief requires four deliverables. Complete every checkbox before submitting.

## Code and changelog

- [ ] Public or judge-accessible repository points to the final reviewed commit.
- [ ] README clearly names the intended user, bottleneck, practical value, and no-auto-merge boundary.
- [ ] All agent instructions and workflow templates are included.
- [ ] Pre-hackathon work and hackathon additions are clearly separated.
- [ ] Improvement changelog contains every meaningful kept or removed experiment.
- [ ] Main failure mode and hot take link to evidence.
- [ ] License and third-party service terms have been reviewed.

## Reproduction

- [ ] A second person completes setup from a clean environment.
- [ ] Node.js, provider/model, runner, timeout, and repository starting commit are recorded.
- [ ] Exact solution, baseline, and evaluation commands work as written.
- [ ] Expected outputs, approximate runtime, and estimated cost are documented.
- [ ] Judge-access path works without company-only data or permissions.

## Evaluation

- [ ] All ten baseline cases are executed in declared order.
- [ ] All ten final cases are executed under matching controlled conditions.
- [ ] Every criterion and required check has redacted evidence.
- [ ] Comparison reports `complete=true` and `comparable=true`.
- [ ] Failures and timeouts remain in the result set.
- [ ] At least one challenging case and its lesson are highlighted.
- [ ] Every numerical claim links to a curated evidence artifact.

## Video - maximum five minutes

- [ ] Starts with user, bottleneck, and simple baseline.
- [ ] Shows one realistic execution from Slack request to reviewable result.
- [ ] Shows planning, human checkpoint, coding, validation, verification, and PR evidence.
- [ ] Shows final baseline comparison and brief changelog.
- [ ] Identifies the most valuable change and one experiment removed or rejected.
- [ ] Contains captions and readable zoom levels.
- [ ] Reveals no credentials, private identifiers, or proprietary code.
- [ ] Link works in a signed-out browser and duration is at most five minutes.

## Agent trajectories

- [ ] Includes every agent role actually used: planner, coder, verifier, and repair pass where demonstrated.
- [ ] Shows instructions, relevant context, tool actions/results, structured output, and final outcome.
- [ ] Includes feedback, retry/repair, clarification, or approval checkpoints.
- [ ] Distinguishes provider claims from deterministic evidence.
- [ ] All content is redacted and connected to a fixed evaluation case.

## Safety and final review

- [ ] Human approval precedes configured consequential work, and human PR review remains mandatory.
- [ ] No automatic merge or deployment exists.
- [ ] Submission uses synthetic/public/approved data only.
- [ ] Credential-pattern scan and manual secret review pass.
- [ ] `npm run lint`, `npm run typecheck`, and `npm test` pass.
- [ ] Repository-wide formatting status is disclosed or fixed before submission.
- [ ] All links and judge permissions are tested.
